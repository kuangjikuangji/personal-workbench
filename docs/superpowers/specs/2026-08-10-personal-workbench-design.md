# 个人工作学习工作台 React PWA 设计规格

## 1. 目标与范围

将现有纯 HTML/CSS/JavaScript 工作台重构为 React + TypeScript 的本地优先 PWA。首版在本机运行，可从 Chrome/Edge 安装为桌面应用，也可在手机浏览器安装到主屏幕。首版不接入 Supabase、不迁移旧版浏览器数据，但数据访问边界必须允许后续增加 Supabase 增量同步。

首版包含概览、待办、日历、课表、系室管理、科研导师、个人科研、灵感记录、教学备课、学生管理、设置和数据导入导出。微信集成采用“粘贴对话文本、智能解析、预览确认后导入”的本地替代方案；不监听个人微信消息。

## 2. 技术方案

- 构建与界面：Vite、React、TypeScript、React Router。
- 本地数据：Dexie 封装 IndexedDB，每类业务对象使用独立表。
- 服务端状态读取：TanStack Query 负责查询缓存、失效和刷新。
- 界面状态：Zustand 只保存筛选条件、当前学期、弹窗、主题和导航状态。
- 表单与校验：React Hook Form + Zod。
- 日历：FullCalendar，支持月、周、日视图和拖动调整。
- PWA：Vite PWA 插件和 Service Worker，缓存应用静态资源并支持离线启动。
- 导出：SheetJS 生成 `.xlsx`；CSV 使用 UTF-8 BOM；JSON 用于完整备份与恢复。
- 测试：Vitest、React Testing Library、Playwright。

页面不得直接调用 Dexie。每个功能模块通过 Repository 接口读写数据。首版提供本地 Repository；未来的 Supabase 同步服务复用相同领域类型，并依据记录的 UUID 与更新时间进行增量同步和冲突判断。

## 3. 导航与视觉布局

采用“A · 效率工作台”布局。

桌面端使用固定侧栏、顶部快捷操作区和宽内容区。侧栏按“首页、日程、组织管理、学习、设置”分组；顶部持续提供搜索、快速新建和通知入口。概览页展示今日待办、逾期事项、今日课程、角色统计、今日时间轴与快捷入口。系室管理和学生管理可使用完整宽度显示数据表格。

手机端使用“概览、待办、日历、管理、我的”五个底部入口，次要页面放入抽屉菜单。右下角浮动按钮打开快速新建菜单。桌面表格在手机端转换为卡片列表；批量操作进入独立选择模式，避免在窄屏中堆叠复选框和按钮。

角色颜色在全应用保持一致：院长助理、系主任、个人待办各有固定颜色，同时使用文字标签，不能只依赖颜色传达归属。课程采用独立颜色。界面支持浅色和深色主题，并满足键盘操作、焦点可见和表单标签可读等基本无障碍要求。

## 4. 功能设计

### 4.1 概览

概览显示今日未完成待办、逾期事项、今日有效课程、各角色未完成数量和按时间排序的今日时间轴。顶部“快速新建”支持新增待办、灵感、教师记录和学生记录。点击摘要卡片进入已带对应筛选条件的目标页面。

### 4.2 待办与微信文本导入

待办支持新增、编辑、删除、完成、恢复、搜索和按角色、状态、日期、优先级筛选。提供列表视图和看板视图。每条记录包含标题、说明、归属角色、开始与结束时间、提醒时间、优先级和状态。

保存带时间的待办前，同时检查其他未完成待办和有效课程。存在重叠时列出冲突对象，用户可以取消或明确选择继续保存。没有结束时间的待办按 30 分钟计算冲突区间。

微信导入允许粘贴多行对话文本，本地解析日期、时间范围、角色标记和内容。解析结果必须先展示预览，用户逐项勾选后才写入数据库。无法确定角色时归为个人待办；无法确定日期时标记为待确认，不能静默使用当天日期。

### 4.3 日历与提醒

日历提供月、周、日三种视图。月视图的日期格内直接显示待办标题、课程名称和时间，而非仅显示圆点。点击空白日期或时间段快速创建待办；点击事项打开详情；拖动事项调整时间并再次执行冲突检查。

首版提醒只保证应用运行或处于浏览器后台时尽力发送系统通知。应用重新打开时检查未通知的逾期提醒并补报。浏览器通知权限被拒绝时使用应用内通知中心。首版不承诺浏览器和操作系统完全关闭后的准时提醒；该能力留待上线后接入服务端推送。

### 4.4 学期与课表

先创建学期，字段包括名称、开始日期、结束日期、总教学周数和当前状态。课程包含名称、地点、任课教师、星期、开始与结束时间、起止周、周次规则和备注。周次规则支持每周、单周、双周和指定周次。

课程只在学期有效日期和有效教学周中出现在日历。课程日期计算必须以学期开始日所在教学周为第 1 周，并正确处理学期开始日不是星期一的情况。待办冲突检测只检查当天实际发生的课程实例。

### 4.5 系室管理与科研导师

系室管理先维护教师名册，再选择年度查看记录。教师年度记录分为主要工作、例会、教学材料和公共服务四类，每条记录独立保存日期、内容、状态及备注，避免把全年内容合并在一个文本字段中。

用户可以为单个教师新增记录，也可以选择多位教师进行批量操作。例会批量状态包括参会、缺席和请假；材料批量操作为选中教师添加同一材料提交记录；批量操作提交前显示目标教师数量和操作摘要。年度汇总中的“一键补全未填报教师”会基于当前教师名册，为本年度完全没有汇总占位的教师建立空白汇总状态，不复制上一年度数据，也不覆盖已有记录。

每位教师详情包含科研导师页签。用户按学生年级录入该教师指导的本科生，字段包括学生姓名、年级、专业、指导主题、进展状态和备注。导师汇总可以按年度、教师、学生年级和进展筛选，并导出 Excel/CSV。

### 4.6 个人科研与学习方法

文献记录包含题目、作者、来源、年份、链接或 DOI、标签、阅读状态、评分、摘要和阅读笔记。阅读状态为待读、阅读中、已读。学习方法独立保存名称、适用场景、步骤、效果评价和标签，可被文献或备课内容引用，但删除学习方法不会删除引用它的业务记录。

### 4.7 灵感记录

灵感支持快速输入正文、标签、置顶和归档。灵感可以复制转化为待办、科研笔记或备课条目；转化会建立新记录并保存来源标识，原灵感不会自动删除。

### 4.8 教学备课

备课内容按课程组织。每条备课记录包含章节、教学目标、内容提纲、教学资源、课堂活动、计划日期和进度。进度为未开始、进行中、已完成。备课条目可关联已存在课程，但即使课程被删除，备课正文仍需保留。

### 4.9 学生管理

学生管理先维护团队成员，再进入每位学生详情单独添加日常表现。学生记录包含日期、类别、表现等级、具体内容、跟进事项和标签。类别包括任务推进、组会或到岗、学习科研、协作服务及其他；表现等级为积极、正常、需关注。

汇总支持按学生、日期范围、类别和表现等级筛选，导出 Excel/CSV。删除学生前必须明确提示其关联记录数量；用户可以取消、保留为归档学生，或确认同时删除关联记录。默认推荐归档。

### 4.10 设置、安装与数据管理

设置包含主题、通知权限、默认筛选、安装应用入口、示例数据和数据管理。安装按钮仅在浏览器提供安装事件时显示；其他环境展示对应平台的添加到主屏幕说明。

完整 JSON 备份包含数据结构版本和所有业务表。导入流程为选择文件、结构校验、统计预览、确认覆盖。覆盖前自动下载当前数据备份。结构不合法时禁止导入并指出错误。Excel 导出生成真实 `.xlsx` 文件；CSV 必须包含 UTF-8 BOM，保证中文在常见版本 Excel 中正常显示。

Supabase 在首版只保留代码接口和说明，不展示可输入密钥的半成品连接页面。

## 5. 数据模型

所有业务记录使用 UUID 字符串作为主键，并包含 ISO 8601 格式的 `createdAt` 和 `updatedAt`。可归档实体包含 `archivedAt`。数据库包含以下表：

- `todos`：`Todo`。
- `semesters`：`Semester`。
- `courses`：`Course`。
- `teachers`：`Teacher`。
- `teacherRecords`：`TeacherRecord`，通过 `teacherId` 和 `year` 关联教师。
- `mentorships`：`Mentorship`，通过 `teacherId` 和 `academicYear` 关联教师。
- `researchItems`：`ResearchItem`。
- `learningMethods`：`LearningMethod`。
- `ideas`：`Idea`。
- `lessonPlans`：`LessonPlan`。
- `students`：`Student`。
- `studentRecords`：`StudentRecord`。
- `settings`：键值式 `AppSetting`。

Repository 负责事务、关联检查和删除策略；领域服务负责教学周展开、时间冲突、批量操作、微信文本解析和导出数据整形。React 组件不包含这些业务算法。

## 6. 数据流与一致性

表单先通过 Zod 校验，再调用领域服务或 Repository。写入成功后使对应 TanStack Query 缓存失效，并由页面重新读取 IndexedDB。只有数据库事务成功后才显示成功提示。

批量操作必须在单个 IndexedDB 事务中完成：全部成功后统一刷新，任一写入失败则整体回滚。一键补全必须幂等，重复执行不会生成重复占位。课程展开为运行时日历事件，不把每周实例永久写入数据库。

未来同步时以独立记录为同步粒度，不同步 Zustand 界面状态。`updatedAt` 用于检测并发修改；冲突解决界面和用户账户不属于首版本地范围。

## 7. 异常与恢复

- 字段错误显示在对应输入项旁，并保留用户输入。
- IndexedDB 写入失败时显示持久错误提示，不得显示保存成功。
- 时间冲突列出冲突待办或课程，允许取消或明确覆盖。
- 导入必须先校验和预览，覆盖前生成可下载备份。
- PWA 新版本下载后提示用户主动重载，不强制刷新正在编辑的页面。
- 通知权限拒绝、浏览器不支持通知或 Service Worker 不可用时，退化为应用内提醒。
- 空列表、无搜索结果、首次使用和数据加载失败分别使用明确的空状态或错误状态。

## 8. 测试策略

Vitest 单元测试覆盖教学周、单双周、指定周、跨月日期计算，待办与课程冲突，微信文本解析，一键补全幂等性，批量记录事务，以及导出数据整形与导入结构校验。

React Testing Library 覆盖核心表单校验、筛选、确认对话框、批量选择、手机卡片布局的交互状态，以及数据库失败时不显示成功反馈。

Playwright 端到端测试覆盖：

1. 新建三类角色待办并在日历格内看到完整标题。
2. 录入学期课程并验证单双周显示和时间冲突提示。
3. 建立教师名册、一键补全、批量设置例会状态、批量添加材料。
4. 给教师录入分年级本科生指导信息并导出汇总。
5. 给学生单独添加表现记录并导出筛选结果。
6. 新建文献、学习方法、灵感和备课内容，刷新后数据仍存在。
7. 安装清单有效，断网后可再次启动应用并读取本地数据。
8. 在桌面与手机视口下完成导航和关键新增流程。

## 9. 完成标准

- 所有约定模块均可新增、查看、编辑和按各自规则删除或归档。
- 日历直接显示待办和有效课程，时间冲突判断正确。
- 系室批量操作、一键补全、科研导师和学生汇总可用。
- Excel、CSV 和 JSON 导出内容正确，JSON 恢复经过校验和确认。
- 刷新与离线重开后本地数据仍保留。
- Chrome/Edge 可安装为 PWA，手机浏览器可添加到主屏幕。
- 核心单元、组件和端到端测试通过。
- 首版不包含真实 Supabase 同步、账号系统、服务端推送或个人微信自动监听。
